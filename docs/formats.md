# Поддерживаемые форматы и пайплайны конвертации

Just Convert выполняет полный спектр преобразований видео, аудио и графических форматов через оптимизированные конвейеры обработки. Каждый конвейер спроектирован с учетом минимизации потерь качества, интеллектуального анализа метаданных и максимальной производительности оборудования.

Техническая реализация сосредоточена в каталоге [`src/JustConvert.Core/Converters/`](../src/JustConvert.Core/Converters/), где независимые конвертеры размещены на верхнем уровне, а вспомогательные сервисы взаимодействия с утилитами и анализа потоков вынесены в подкаталог [`Tools`](../src/JustConvert.Core/Converters/Tools/).

## 1. Пайплайны конвертации видео

Архитектура видеоконвертера [`VideoConverter.cs`](../src/JustConvert.Core/Converters/VideoConverter.cs) построена вокруг анализа входного потока и выбора оптимального пути кодирования. Перед запуском процесса компонент [`MediaProbe.cs`](../src/JustConvert.Core/Converters/Tools/MediaProbe.cs) определяет параметры цветового пространства, наличие HDR-метаданных, структуру аудиодорожек и кодеки источника.

```powershell
just-convert.exe convert "source.mov" --to mp4-h264
```

### Пайплайн тонемаппинга HDR и HLG в SDR

При обнаружении широкого цветового охвата BT.2020, кривых гаммы SMPTE 2084, стандартов вещания ARIB STD-B67 или логарифмических профилей камер Apple Log конвертер автоматически подключает фильтр тональной компрессии. Преобразование выполняется в цветовое пространство BT.709 с ограничением телевизионного диапазона, восьмибитной упаковкой YUV420P и явным тегированием цветовых параметров контейнера.

```bash
-vf "scale=out_color_matrix=bt709:out_range=tv,format=yuv420p,setparams=color_primaries=bt709:color_trc=bt709:colorspace=bt709" -color_primaries:v bt709 -color_trc:v bt709 -colorspace:v bt709
```

Интерполяция цветоразностных компонентов для всех масштабирований и матричных переходов выполняется с флагами сплайнового сглаживания и повышенной точности округления, что исключает появление ступенчатых артефактов и постеризации на градиентах.

```bash
-sws_flags spline+accurate_rnd+full_chroma_int
```

### Пайплайн программного кодирования CPU

Для универсального кодирования видеопотока используется стандарт H.264 с коэффициентом постоянного качества 23, сбалансированным профилем скорости и переносом метаданных для оптимизации потокового воспроизведения через флаг быстрого старта. Звуковая дорожка в этом конвейере сжимается кодеком AAC с битрейтом 192 килобита в секунду.

```bash
-c:v libx264 -crf 23 -preset medium -c:a aac -b:a 192k -movflags +faststart
```

Высокоэффективное кодирование H.265 использует кодек libx265 с тегом совместимости hvc1 для корректного воспроизведения в проигрывателях Apple QuickTime и Windows Media. Для формата WEBM применяются кодеки VP9 с многопоточным распараллеливанием и AV1 на базе библиотеки SVT-AV1 с тюнингом визуального качества. Профессиональный монтажный монтаж поддерживается через Apple ProRes профилей 422 и 4444 с несжатым звуком PCM.

```bash
-c:v libsvtav1 -crf 23 -preset 6 -svtav1-params tune=0 -c:a libopus -b:a 128k
```

### Пайплайны аппаратного ускорения GPU

При наличии графических ускорителей Just Convert активирует аппаратные конвейеры кодирования, подробное описание которых представлено в документе [`hardware_acceleration.md`](hardware_acceleration.md). Для карт NVIDIA NVENC применяется двухпроходный анализ полного разрешения со стабилизацией B-кадров и пространственно-временной адаптацией квантования, для Intel QSV задействуются адаптивные I- и B-кадры, а для AMD AMF настраивается точный контроль квантования кадров при сбалансированном профиле качества.

### Пайплайны ремуксирования, перекодирования и раскадровки

Пайплайн быстрого ремуксирования (`remux`) выполняет переупаковку медиапотоков в контейнеры MP4, MKV, MOV или WEBM без декодирования и повторного сжатия через флаг прямого копирования (`-c copy`), обеспечивая мгновенную смену контейнера с сохранением оригинального качества и метаданных. При запуске ремуксирования отображается интерактивное диалоговое окно настройки (`ConversionOptionsDialog`), позволяющее выбрать целевой контейнер, включить или отключить копирование видео, аудио и субтитров, активировать флаг быстрого старта (`+faststart`) для MP4/MOV, настроить суффикс `[Remux]` и сохранить выбор.

```bash
-map 0:v? -map 0:a? -map 0:s? -c copy -movflags +faststart -map_metadata 0
```

Пайплайн прямого перекодирования (`reencode`) выполняет повторное кодирование видео в тот же контейнер с активными настройками качества и кодека без вызова дополнительных диалоговых окон. Кроме того, Just Convert поддерживает конвертацию видео в идентичный контейнер (например, `mp4 -> mp4`, `mkv -> mkv`, `webm -> webm`, `mov -> mov`), что позволяет пользователю целенаправленно изменять используемый кодек (например, переводить AV1 или VP9 в совместимый H.264).

Компонент `MediaProbe.cs` автоматически определяет кодеки входного видео и звука, а `QualityEstimator.cs` форматирует понятное представление (`H.264`, `H.265/HEVC`, `AV1`, `VP9`, `ProRes`, `AAC`, `FLAC`, `MP3` и др.), которое отображается в строке сведений об исходном файле диалогового окна конвертации.

Пайплайн извлечения кадров (`frames`, `frames-png`, `frames-jpg`, `frames-webp`, `frames-bmp`, `frames-tiff`) сохраняет раскадровку видеофайла с интервалом в одну секунду в виде последовательности изображений в отдельную подпапку. Пользователь может выбрать целевой формат изображений: PNG (без потерь), JPEG (сжатый), WebP (эффективный веб-формат), BMP (несжатый растр) или TIFF (полиграфический формат высокого качества). При необходимости выбор формата можно запомнить для последующих операций.

### Пайплайн извлечения аудиодорожки из видео

При выборе аудиоформата в качестве цели для видеофайла управление передается логике формирования звуковых параметров из домена аудиоконвертера. Из видеопотока выделяется первая основная аудиодорожка и транскодируется в выбранный формат с сохранением метаданных без привлечения видеокодеков.

## 2. Пайплайны конвертации аудио

Аудиоконвертер [`AudioConverter.cs`](../src/JustConvert.Core/Converters/AudioConverter.cs) реализует специализированные конвейеры для обработки звука без потерь и со сжатием. Определение разрядности, частоты дискретизации, битрейта и встроенных обложек альбомов выполняется сервисом [`MediaProbe.cs`](../src/JustConvert.Core/Converters/Tools/MediaProbe.cs).

```powershell
just-convert.exe convert "album_track.flac" --to m4a
```

### Пайплайн Lossless в Lossless (Hi-Res Audio)

Конвертация между форматами без потерь качества (FLAC, WAV, ALAC в контейнере M4A, AIFF) автоматически определяет глубину квантования источника. Если исходный файл записан в разрядности 24 бита или выше, выходной кодек переключается на 24-битный режим, предотвращая транкейты и потерю динамического диапазона.

```bash
-map 0:a:0 -c:a pcm_s24le -map_metadata 0
```

Для формата FLAC применяется сжатие с сохранением исходной разрядности. Для Apple Lossless внутри контейнера M4A подключается кодек alac. В конвейерах FLAC, ALAC и AIFF встроенные графические обложки альбомов автоматически переносятся в выходной файл с сохранением разметки ID3v2 и вложенных метаданных.

```bash
-map 0:a:0 -map 0:v? -c:a alac -c:v copy -disposition:v:0 attached_pic -map_metadata 0
```

### Пайплайн Lossless в Lossy

Сжатие звука без потерь в форматы с потерями выполняет преобразование на максимальных качественных пресетах. Конвертация в MP3 использует кодировщик LAME с предельным битрейтом 320 килобит в секунду, разметкой ID3v2 третьей версии и привязкой обложки альбома.

```bash
-map 0:a:0 -map 0:v? -c:a libmp3lame -b:a 320k -c:v copy -disposition:v:0 attached_pic -id3v2_version 3
```

Сжатие в современный кодек OPUS использует адаптивный переменный битрейт с автоматическим ограничением предельной скорости до 192 килобит в секунду для монофонических записей и до 256 килобит в секунду для стереофонических треков, обеспечивая студийную прозрачность звука при минимальном размере файла. Для контейнера OGG задействуется кодек Vorbis с девятым уровнем шкалы качества.

```bash
-map 0:a:0 -c:a libopus -b:a 256k -vbr on -map_metadata 0
```

### Пайплайн Lossy в Lossy и умный контейнер M4A

При конвертации между форматами со сжатием алгоритм анализирует битрейт источника и подбирает ближайшее стандартное значение без избыточного апскейла битрейта. В диалоге параметров аудио доступен режим «Ближайший как у каждого оригинала» (значение битрейта 0 / авто), в котором конвертер динамически считывает битрейт каждого трека и подбирает эквивалентную скорость потока индивидуально. Если входной поток уже закодирован в AAC, а целевым форматом выбран M4A или AAC, конвейер выполняет прямое копирование аудиоданных без повторного пережатия.

Контейнер M4A реализует умный гибридный выбор. Если источник является несжатым звуком или форматом без потерь, кодирование идет в ALAC, а если источник содержит звук с потерями, конвертер сжимает поток в AAC с адаптивным битрейтом до 320 килобит в секунду.

## 3. Пайплайны конвертации изображений

Графический конвертер [`ImageConverter.cs`](../src/JustConvert.Core/Converters/ImageConverter.cs) использует движок ImageMagick для преобразования растровых, векторных и профессиональных графических форматов.

```powershell
just-convert.exe convert "photo.heic" --to jpg
```

### Пайплайн нормализации ориентации и цветопередачи

Все операции растрового конвейера начинаются с применения автоматической ориентации изображения по служебному тегу EXIF. Это гарантирует правильное вертикальное или горизонтальное положение снимков, сделанных на смартфоны и цифровые камеры, даже при конвертации в форматы без поддержки метаданных ориентации.

Для предотвращения искажения оттенков кожи и выцветания кадров с широким цветовым охватом Display P3 или Adobe RGB конвейер выполняет стандартизацию цветового пространства в sRGB.

```bash
-auto-orient -colorspace sRGB
```

### Пайплайн обработки RAW-снимков камер

Преобразование сырых форматов камер (CR2, CR3, NEF, ARW, DNG) построено по гибридной схеме. В первую очередь конвертер извлекает встроенный полноразмерный JPEG-снимок, сформированный процессором фотоаппарата с учетом аппаратного баланса белого, стилей производителя и оптических коррекций объектива. Это обеспечивает мгновенную обработку и точную передачу цветов.

Если встроенное полноразмерное превью отсутствует, ImageMagick автоматически переключается на алгоритм дебайеризации сенсора с программной реконструкцией матрицы и нормализацией экспозиции.

### Пайплайн векторной графики и многослойных документов

Растеризация векторного формата SVG выполняется с сохранением прозрачности альфа-канала для выходных форматов PNG, WEBP и ICO. При конвертации вектора в форматы без поддержки прозрачности выполняется принудительное сведение слоев на белый фон.

Для документов Adobe Photoshop в формате PSD конвейер считывает нулевой композитный слой документа, исключая создание разрозненного набора файлов из отдельных внутренних слоев проекта.

```bash
"input.psd[0]" -auto-orient -colorspace sRGB "output.png"
```

### Пайплайн генерации многослойных иконок Windows

Конвертация в формат иконки ICO задействует специализированный генератор масштабов. Вместо создания единичного фиксированного слоя инструмент генерирует полноценный многослойный файл с шестью слоями разрешения от 16 до 256 пикселей, что обеспечивает четкое отображение иконки в любых режимах проводника Windows 11.

```bash
-auto-orient -background transparent -define icon:auto-resize=256,128,64,48,32,16 "output.ico"
```

### Пайплайн растрового сжатия и оптимизации

Конвертация в растровые форматы со сжатием с потерями (`JPEG`, `WebP`, `AVIF`, `JPEG 2000`) поддерживает гибкую настройку степени сжатия от 1 до 100%. При первой конвертации в один из этих форматов отображается компактный диалог выбора качества (`ImageQualityDialog.xaml`) с ползунком, описанием баланса качества/размера, опцией запоминания выбора для конкретного формата и переключателем суффикса качества. При запоминании последующие конвертации выполняются автоматически без диалога. Значения по умолчанию: 92% для JPEG со сведением фона, 85% для WebP, 80% для AVIF, 85% для JPEG 2000. Для PNG применяется уровень компрессии 95%, для TIFF — LZW-сжатие без потерь. Режим перекодирования в тот же формат дополнительно очищает файл от избыточных метаданных с помощью параметра стриппинга.

## 4. Именование выходных файлов и разрешение коллизий

Формирование имен выходных файлов централизовано в компоненте [`OutputFileNameHelper.cs`](../src/JustConvert.Core/Converters/OutputFileNameHelper.cs) по стандарту:
`<ИмяИсходногоФайла> [<КОДЕК - ПАРАМЕТРЫ>]<расширение>` (или без суффикса в скобках, если у формата нет дополнительных параметров либо суффикс отключен в настройках). Название контейнера или расширения внутри скобок не дублируется.

Примеры:

- Видео: `video [H.264 - CQ 23].mp4`, `video [H.265 NVENC - CQ 23].mp4`, `video [ProRes 422].mov`, `video [Remux].mp4`, `video.gif`
- Извлечение кадров: каталог `video [Frames]/` с файлами `video_%04d.png` (или `.jpg`, `.webp`, `.bmp`, `.tiff` в зависимости от выбранного формата)
- Аудио: `track [320k].mp3`, `track [24-bit].flac`, `track [Lossless].flac`, `track [ALAC - Lossless].m4a`, `track [PCM 16-bit].wav`
- Изображения (с суффиксами по умолчанию): `photo [Q92].jpg`, `photo [Q85].webp`, `photo [Q80].avif`, `photo [Q85].jp2`, `icon [Multi-layer].ico`, `document [LZW].tiff`, `photo.png`, `photo [Reencode].jpg`
- Изображения (при отключенном суффиксе качества): `photo.jpg`, `photo.webp`, `photo.avif`, `photo.png`

При возникновении коллизий (если целевой файл или папка уже существуют) компонент автоматически добавляет порядковый индекс:
`video [H.264 - CQ 23] (1).mp4`, `video [H.264 - CQ 23] (2).mp4`, `photo [Q92] (1).jpg`
